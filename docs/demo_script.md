# Web Demonstration Script (5-Step Walkthrough)

This script provides a step-by-step presentation guide for professors and evaluators demonstrating the full capabilities of the **SQL Query Compiler & Optimizer Web Application**.

---

### Step 1: Open the Page & Run the Default Query
1. Start the web application:
   ```bash
   ./run_web.sh
   ```
2. Open your web browser to **`http://127.0.0.1:5000`**.
3. Notice:
   - The left sidebar displays the pre-seeded sample tables: `courses`, `dept`, `enrollments`, and `students` with their schema types and row counts.
   - The query editor contains the pre-filled join query:
     ```sql
     SELECT s.name, s.gpa, d.dname 
     FROM students s 
     JOIN dept d ON s.dept_id = d.id 
     WHERE s.age > 20;
     ```
4. Click **Run Query** (or press `Ctrl+Enter`).
5. **Expected Outcome:**
   - The **Result** tab displays the returned rows table.
   - Execution time (e.g. `~0.15 ms`) and row count (`154 rows`) are displayed on badges.
   - Click **Export CSV** to download the query results as a CSV file.

---

### Step 2: Upload a New CSV Table & Query It
1. In the left **Tables** panel, click the **+ Add Table** button.
2. Under the **(a) Upload CSV** tab:
   - Table Name: `professors`
   - Select or create a sample CSV file `professors.csv`:
     ```csv
     id,name,department,salary
     1,Dr. Ada Lovelace,CS,120000
     2,Dr. Alan Turing,CS,125000
     3,Dr. Emmy Noether,Math,115000
     ```
3. Click **Upload & Register Table**.
4. **Expected Outcome:**
   - The modal closes and `professors` appears in the left sidebar with `3 rows` and inferred types (`id (INT)`, `name (STRING)`, `department (STRING)`, `salary (INT)`).
   - Click the **Preview** button next to `professors` to inspect its schema and rows.
5. In the query editor, run:
   ```sql
   SELECT name, salary FROM professors WHERE salary >= 120000;
   ```
6. **Expected Outcome:**
   - Returns 2 rows (`Dr. Ada Lovelace` and `Dr. Alan Turing`).

---

### Step 3: Switch to the AST & Logical Plan Tabs
1. Select the **"2. Constant Folding & Arithmetic"** example from the **Examples** dropdown:
   ```sql
   SELECT name, age, 2 + 3 * 4 AS calc FROM students WHERE age > 18 + 2;
   ```
2. Set Mode to **Verbose** and click **Run Query**.
3. Click the **AST** tab:
   - Observe the parsed syntax tree generated by the Bison LALR(1) parser showing `BinOp(+)`, `BinOp(*)`, and literal nodes.
4. Click the **Logical Plan** tab:
   - Observe the relational algebra tree before optimization: `Project`, `Filter`, and `Scan`.
5. Click the **Optimized Plan** tab:
   - Observe the rule list: `Constant Folding` fired.
   - The expression `2 + 3 * 4` was folded into literal `14`, and `18 + 2` into `20` at compile time!

---

### Step 4: Run an Error Query & Show the Error Panel
1. Enter an intentional syntax error into the editor:
   ```sql
   SELECT FROM dept;
   ```
2. Click **Run Query**.
3. **Expected Outcome:**
   - The prominent red **Error Panel** appears:
     - Badge: **SYNTAX ERROR**
     - Location: **Line 1, Col 8**
     - Message: `syntax error, unexpected FROM (near 'FROM')`
     - Line 1 is highlighted in red inside the CodeMirror editor.
4. Now enter a semantic error:
   ```sql
   SELECT non_existent_column FROM dept;
   ```
5. Click **Run Query**.
6. **Expected Outcome:**
   - Badge: **SEMANTIC ERROR**
   - Message: `unknown column 'non_existent_column'` with "Did you mean...?" suggestion if close.

---

### Step 5: Optimizer Comparison in Compare Mode
1. Select the **"5. Three-Table Join & Predicate Pushdown"** query from the **Examples** dropdown:
   ```sql
   SELECT s.name, c.cname, e.grade 
   FROM students s 
   JOIN enrollments e ON s.id = e.student_id 
   JOIN courses c ON e.course_id = c.id 
   WHERE s.age > 20 AND 1 = 1;
   ```
2. Set Mode to **Compare** and click **Run Query**.
3. Click the **Compare** tab:
4. **Expected Outcome:**
   - **Side-by-Side View:**
     - Left: **Unoptimized Plan** ($O(N \times M)$ nested-loop joins, unpushed filters, tautology `1 = 1` evaluated at runtime).
     - Right: **Optimized Plan** (Tautology pruned, filters pushed below joins, equi-joins converted to Hash Joins).
   - **Metrics Highlight:**
     - Both return the exact same row count (`~154 rows`).
     - A green badge displays the percentage reduction in rows processed (e.g. `~45% - 50% reduction`).
     - Clear operator statistics display `rows_in` and `rows_out` for each relational node.
